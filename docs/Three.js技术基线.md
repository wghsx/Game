## 二、渲染基线

| 项 | 值 |
| --- | --- |
| 相机 | PerspectiveCamera，视场角 28° |
| 初始机位 | (58, 48, 58)，即等距 45° |
| 跟随偏移 | isoOffset = (58, 48, 58) |
| 全景机位 | (88, 72, 88) |
| 控制器 | OrbitControls，阻尼 0.06，俯角限制在水平线上 0.03 弧度内 |
| 色调映射 | ACESFilmicToneMapping，曝光 1.18 |
| 阴影 | PCFShadowMap |
| 雾 | FogExp2，色值 0xdceaf6，密度 0.0022 |
| 光源 | HemisphereLight + AmbientLight + DirectionalLight 三件套 |

三个时段预设（午后 / 落日 / 霓虹）改的是背景色、雾色、日光色与强度、半球光色、环境光强度这一组参数。**时钟推进到时段边界时，光照会自动跟着切**，见下节。

## 四、模拟内核

`src/simulation.js` 是这一轮新增的，把 HUD 上那堆写死的展示值换成了真的计算。

### 4.1 职责边界

- 内核只管规则和数字，**不碰任何 Three.js 对象**。想换渲染层，内核不用改。
- `main.js` 只做三件事：初始化内核、把玩家动作转成内核调用、把内核快照刷到 HUD。

### 4.2 时间

| 项 | 值 |
| --- | --- |
| 映射 | 1 真实秒 = 1 游戏分钟 |
| 一游戏日 | 1440 游戏分钟 = 24 真实分钟 |
| 日结算时刻 | 04:00，不是 00:00（居酒屋跨零点营业） |
| 倍速 | 1× / 2× / 4× |

### 4.3 已实现的系统

| 系统 | 状态 |
| --- | --- |
| 时间与天气 | 时钟自动推进，天气每天换，樱吹雪把客流乘 1.3 |
| 住户与人口 | 42 户，满意度高会搬进来，低会搬走 |
| 店铺经营 | 4 家店，各有吸引力、日营业基准、营业时段 |
| 经济收支 | 抽成 15% + 日租 + 维护费，04:00 结算 |
| 满意度 | 居住 / 商业齐全度 / 环境 / 通勤四维，按性格权重合成 |
| 街区等级与星级 | 等级是繁荣度，星级是性格纯度 |
| 巡视配额 | 每天 3 次，亲手巡视当天客流 +10%，不巡视的店维护度会涨 |
| 街区性格 | 四种可切换，切换会重排满意度权重 |
| 街区争霸 | 控制度每日按双方影响力消长，单日上限 3%，跌破 50% 持续 10 天判负 |
| 存档 | localStorage，只存真源，派生值读档重算 |

### 4.4 接线方式

`main.js` 里用 `window.sim` 暴露了内核实例，所以在浏览器控制台可以直接调参：

```js
sim.snapshot()            // 看当前全部状态
sim.minute = 900          // 拨时钟
sim.funds = 9999999       // 改钱
sim.control = 0.95        // 试一下吞并对手
sim.settle()              // 手动跑一次日结算
```

## 七、当前缺口

- 街区争霸只有数字，地图上没有可视化，玩家看不到「自己的颜色在往外推」。
- 店铺只有 4 家，等级和经济的成长空间不足。
- 巡视配额的「发现问题」还没做：现在不巡视只是维护度上涨，没有具体事件。
- 玩家角色还是场景里那个人形，没有装扮与形象系统。
- 主力玩法（街区性格带来的扩张武器差异）还只是权重表，没有可感知的表现。
