## 三、资产管线

| 项 | 要求 |
| --- | --- |
| 格式 | `.glb`，贴图内嵌 |
| 坐标轴 | Y 轴朝上，-Z 轴朝前（模型正面 +Z） |
| 原点 | 模型底部几何中心 |
| 材质 | PBR 纯色 + 自发光，不用贴图 |
| 命名 | 语义名，如 `shop_ramen_2f.glb`、`res_danchi_4f.glb` |
| 生成 | `tools/blender_kit.py`，Blender 5.2 跑一遍出全部 49 件 |

资产源是 `assets/SakuraBlock_Kit.blend`，导出结果在 `public/models/`，清单见《建模管线与资产清单》。

招牌是唯一需要贴图的地方。模型里留一块空色板，运行时由 `src/assets.js` 读它的包围盒，生成 Canvas 店名贴图盖上去，所以一套门脸能服务多家店。

原来的顶点色、1 格 = 1 米、面数预算那一套全部作废，见 ADR-0012。

## 四、模拟内核

`src/simulation.js` 是这一轮新增的，把 HUD 上那堆写死的展示值换成了真的计算。

### 4.1 职责边界

- 内核只管规则和数字，**不碰任何 Three.js 对象**。想换渲染层，内核不用改。
- `main.js` 只做三件事：初始化内核、把玩家动作转成内核调用、把内核快照刷到 HUD。

### 4.2 时间

| 项 | 值 |
| --- | --- |
| 映射 | 1 真实秒 = 1 游戏分钟 |
| 一游戏日 | 1440 游戏分钟 = 24 真实分钟 |
| 日结算时刻 | 04:00，不是 00:00（居酒屋跨零点营业） |
| 倍速 | 1× / 2× / 4× |

### 4.3 已实现的系统

| 系统 | 状态 |
| --- | --- |
| 时间与天气 | 时钟自动推进，天气每天换，樱吹雪把客流乘 1.3 |
| 住户与人口 | 42 户，满意度高会搬进来，低会搬走 |
| 店铺经营 | 4 家店，各有吸引力、日营业基准、营业时段 |
| 经济收支 | 抽成 15% + 日租 + 维护费，04:00 结算 |
| 满意度 | 居住 / 商业齐全度 / 环境 / 通勤四维，按性格权重合成 |
| 街区等级与星级 | 等级是繁荣度，星级是性格纯度 |
| 巡视配额 | 每天 3 次，亲手巡视当天客流 +10%，不巡视的店维护度会涨 |
| 街区性格 | 四种可切换，切换会重排满意度权重 |
| 街区争霸 | 控制度每日按双方影响力消长，单日上限 3%，跌破 50% 持续 10 天判负 |
| 存档 | localStorage，只存真源，派生值读档重算 |

### 4.4 接线方式

`main.js` 里用 `window.sim` 暴露了内核实例，所以在浏览器控制台可以直接调参：

```js
sim.snapshot()            // 看当前全部状态
sim.minute = 900          // 拨时钟
sim.funds = 9999999       // 改钱
sim.control = 0.95        // 试一下吞并对手
sim.settle()              // 手动跑一次日结算
```

## 六点五、路面与街道

沥青、人行道砖都是 Canvas 现画的贴图，配 roughnessMap 与 normalMap。干燥时 `roughness` 必须给 1.0，让贴图说话；写死一个低值会把粗糙度贴图乘掉，路面立刻变成塑料。

标线不画进贴图。108 米的路平铺一张带标线的图，标线会被拉长，所以标线单独用平面几何铺在路面上，再合并成两个 mesh。

街道家具（电线杆、电线、路灯、信号灯、路镜、邮筒、消防栓、防撞柱、护栏、止まれ、车架、垃圾桶、井盖、交通锥、贩卖机）由 `dressStreet()` 统一摆放，摆完按材质烘焙成一整批。

## 七、当前缺口

- 店铺内景没做，玻璃后面是暗壁加货架剪影，进去不了。
- 角色仍是程序化方块人，只有四肢摆动，没有骨骼动画。
- 街区性格带来的扩张差异还停在权重表，玩家看不到"游客街和深夜街到底哪不一样"。
- 天气与季节只改了植被色调和光照参数，没有落樱堆积、积雪这类实感变化。
- 存档只存了资金、天数、控制度，店铺加层、提案、隐患进度都没有落盘。
