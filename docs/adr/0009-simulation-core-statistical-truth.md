# 模拟内核形态：统计层为真源，连续与日结算分两条通道

状态：已采纳

模拟经营类最容易踩的坑，是把街上每个 NPC 都做成独立 agent。真做下去会发现两件事：玩家一屏只看得到 40 个人，养几百上千个 agent 的算力全花在了看不见的地方；而且 agent 越多，行为越难调，最后出现一堆无法解释的怪象。

决定：**模拟真源只有户和店两层，屏幕上的 NPC 是表现层**，从统计模型按概率抽出来演，走完即回收；玩家按 E 交互时才临时给这一个 NPC 生成个体档案。时间推进分两条通道，连续通道每游戏分钟跑玩家看得见的东西（营业状态、人流、天气视觉），日结算通道每游戏日在 04:00 跑经济、人口、满意度与等级。

## Considered Options

- 全 agent 模拟：个体感的理论上限最高，但成本与调试难度都不划算，且收益玩家看不见。
- 纯日结算：性能最好，但「看着店铺慢慢热闹起来」的体感消失，模拟经营的乐趣直接少一半。

## Consequences

- 模拟规模可以远超屏幕可见规模，一屏 40 个 NPC 只是表现层预算，与模拟的人口规模解耦。
- 每个系统都要明确归属哪条通道，新加系统时必须回答这个问题，否则会出现「这个值到底什么时候更新」的混乱。
- 玩家与单个 NPC 的交互是短期特例，不改变世界状态，这限制了后续做「好感度」「NPC 养成」这类玩法的空间。要加就得推翻这一条。
- 结算时刻选在 04:00 而不是午夜，因为居酒屋类店铺跨零点营业；这个细节容易被后人改回 00:00，故记录在此。
- 模拟的确定性使得「重放」成为可能，问题排查和自动化测试都有了抓手。
