# 技术栈改为 Three.js 网页游戏

状态：已采纳（取代 ADR-0001）

前十一条设计文档都建立在「用 Unity 做桌面端 3D 游戏」这个前提上，直到盘点机器时发现真实项目在 `D:\Desktop\Game`：一个 **Three.js + Vite 的浏览器游戏**，包名 `japanese-city-tycoon-3d`，`src/main.js` 已经八十多 KB，场景、角色、交互、音效、HUD 全部就位。

决定：技术上以现有的 Three.js 项目为准，**不做 Unity 迁移**。ADR-0001 关于 Unity 6 LTS 与 PC 首发的内容全部作废。

## Considered Options

- 迁到 Unity：等于把已有的街区场景、角色控制、HUD、音效、交互全部重做一遍，换来的只是打包成桌面程序。收益与成本完全不成比例。
- 保留 Unity 文档当作「将来可能上桌面端」的备选：会让后续每次决策都要考虑两套方案，属于自我消耗。已放弃。

## Consequences

- 发行形态是网页链接，分享成本几乎为零，但也意味着要面对浏览器性能与包体限制。
- 现有的 `japanese_street_scene.blend` 与 `full_district.glb` 是唯一资产源，不再自建低模资产。
- 之前为 Unity 写的《3D资产制作规范》《资产清单与分解》《商铺与街区变体设计》全部作废，见 ADR-0012。
- **玩法设计不受影响**：《数值参数总表》《模拟内核规范》《街区争霸规范》《玩法候选池》《主角设计》讲的是规则不是实现，整份保留。这是「先定玩法再定引擎」这个顺序的红利。
