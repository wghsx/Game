# 美术基线改为 GLB 资产 + 卡通渲染

状态：已采纳（取代 ADR-0002、ADR-0005、ADR-0006、ADR-0007）

被取代的四条分别是：渲染风格（低多边形 + 正交相机 + 平面着色 + 全屏像素化）、画面基准（480×270 虚拟分辨率）、材质策略（顶点色纯色 + 全街共用材质）、光照（全实时不烘焙）。

它们全都服务于一个前提：**自己从零造低模资产**。这个前提不成立。现有场景 `japanese_street_scene.blend` 有 385 个网格、69 个材质、16652 三角面，是 PBR 卡通渲染的成品级日式街区，面数只有我手搓那版的四分之一，细节却多得多。

决定：资产走 **glTF/GLB** 管线，美术基线以现有场景为准。导入规范用项目里已有的一份：

| 项 | 要求 |
| --- | --- |
| 格式 | `.glb`（二进制 glTF，贴图内嵌） |
| 坐标轴 | Y 轴朝上，-Z 轴朝前 |
| 原点 | 模型底部几何中心（地面接触点） |
| 材质 | 烘焙好的 PBR，或卡通手绘贴图 |
| 命名 | `player.glb`、`lawson.glb`、`ramen.glb`、`vending.glb` 这类语义名 |

## Considered Options

- 保留像素化路线：等于把已经做好的高精度场景砸掉重做，而且像素化与「玻璃里能看到货架」这种细节根本互斥。
- 混合两套（远景像素化、近景写实）：风格会撕裂，且要维护两条渲染路径。

## Consequences

- 「全场景共用一个材质」这条合批优势没了，69 个材质意味着更多 draw call，性能要靠合批工具与 LOD 补，不能再靠材质数量作弊。
- 顶点色、1 格 = 1 米的格子系统、面数预算表这些约束全部失效，改为按实际资产量级管理。
- 光照从「不烘焙」变成可以正常用阴影与后处理，画面上限提高了，但要重新做性能预算。
- 《3D资产制作规范》《资产清单与分解》《商铺与街区变体设计》三份文档作废，只保留其中与引擎无关的部分（命名前缀思路、外摆上限 3 件、招牌识别点这些设计判断仍然成立）。
