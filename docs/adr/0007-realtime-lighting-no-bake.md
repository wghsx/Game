# 光照：全实时，不做烘焙

状态：已采纳

游戏有昼夜循环与天气变化（参考图的 HUD 上就带着「15:30 晴」）。常规 3D 项目默认会做光照烘焙来省性能、提画质，但烘焙的前提是场景光照静态不变，这与昼夜玩法直接冲突。

决定：**不做光照烘焙**。用一盏实时定向光 + 环境光，阴影贴图 1024，允许它糊。昼夜变化只改环境光颜色与一层后处理调色，不动态增删光源；夜间店面灯火用自发光材质贴片，不用实时点光源。

## Considered Options

- 烘焙光照贴图：画质收益在像素化后处理之后基本看不出来，却把光照锁死为静态。
- 混合方案（静态烘焙 + 少量实时灯）：流程复杂度翻倍，对这种低模风格属于过度工程。

## Consequences

- 场景可以自由改动结构而不需要重新烘焙，迭代速度快。这条对模拟经营类游戏尤其重要，玩家会不断加建、改建街区。
- 阴影质量被主动放弃，糊是预期效果，后续不要有人去「优化」它。
- 读取光照方案的人会疑惑「为什么一个 3D 游戏没有烘焙数据」，此 ADR 即答案。
