# 建模产出与发现

版本 v0.1 · 2026-10-15 · Blender 5.2.2 LTS（无头模式）

## 一、这一轮做了什么

把 MVP 资产集真正建出来了，不是画图，是能导出进引擎的 FBX。

| 产物 | 位置 |
| --- | --- |
| Blender 参数化建模库 | `tools/sakura_lib.py` |
| 资产生成脚本 | `tools/build_assets.py` |
| 街区拼装与出图脚本 | `tools/build_block.py` |
| 规范自检脚本 | `tools/check_assets.py` |
| 资产源文件 | `assets/SakuraBlock_Assets.blend` |
| FBX 资产，32 个 | `build/fbx/` |
| 预览图，6 张 | `preview/` |

产出方式是全脚本化的。每件资产的尺寸、颜色、原点都由代码决定，不靠手点，所以能复现、能批量改、能自动校验。这是「八十五件资产」这个量级唯一可行的做法。

32 件，不通过 0 件。

逐项检查内容与《3D资产制作规范》第 10 节对应，命名前缀、原点在底面中心、缩放为 1.0、无残留旋转、无负缩放、顶点色 Col 存在、材质共用 M_VertexColor、已三角化不留 n-gon、无平滑着色面、面数在预算内。

## 四、原型暴露的三个规格问题

这三条在写文档时看不出来，建出来才露馅。

### 1. 樱花树冠幅超了

原设计冠幅 1.9 米，而人行道只有 1 米宽。第一版渲染里树把整条街堵死了，人行道上连人都站不下。

已改：冠幅压到 1.32 米，树干 0.26 米，树冠允许稍微悬到车行道上。0.6 米的悬挑在视觉上是自然的，现实里的行道树也这样。

### 2. 建筑进深 1 米不成立

原设计写的是「占地 2×1 格或 2×2 格」，其中 2×1 意味着进深 1 米。真拼出来是个棚子，连门都放不下。

已改：演示街区一律用 2×2 占地（面宽 2 米、进深 2 米），屋顶件相应从 2.3×1.1 改成 2.3×2.3。

**建议把规范里的占地规格统一成只有 2×2**，把 2×1 删掉。留着它只会让人拼出棚子。

### 3. 一米人行道偏窄

树、电杆、垃圾桶、行人全挤在 1 米宽的人行道上，通行面很紧张。当前演示靠限制道具密度凑合过去了，但这是个结构问题。

有两条路，需要裁决：

- 把人行道加宽到 1.5 格，街道横断面从 4 格变 5 格，代价是打破「整数格」这个约定，程序铺路要按半格处理。
- 维持 1 格，把人行道道具密度上限写死进规范，靠数量控制换通行面。

## 六、怎么复跑

```bash
BL="/c/Program Files/Blender Foundation/Blender 5.2/blender.exe"
"$BL" --background --factory-startup --python tools/build_assets.py   # 生成资产并导出 FBX
"$BL" --background --factory-startup --python tools/check_assets.py   # 规范自检
"$BL" --background --factory-startup --python tools/build_block.py    # 拼街区出预览图
```

改任何尺寸只改 `tools/sakura_lib.py` 里的常量或 `build_assets.py` 里对应那一件，重跑即可，不用重建工程。

## 七、预览图怎么读

六张图分三组，每组一张 480×270 的原图和一张 4 倍放大的：

| 组 | 用途 |
| --- | --- |
| block_iso | 全街区等距俯视，看整体密度与天际线 |
| shop_closeup | 门脸近景，看店铺识别点 |
| street_along | 沿街斜看，看街道纵深，最接近参考图构图 |

放大用的是最近邻，所以 1920×1080 那张上的像素块就是最终游戏里的像素大小。1440p 玩家会看到的比这个更粗一点点。

## 八、下一步建议的顺序

1. 先定第四节那第三条，人行道宽度，它影响后面所有街区的摆放规则。
2. 补齐 L2 门脸到 8 套，这是街景不单调的关键。
3. 做像素化后处理，把预览图变成真正的成品观感，也顺便验证 480×270 这个分辨率定得对不对。
4. 角色骨骼留到最后，它最贵，而且前期用方块人也能验证玩法。
