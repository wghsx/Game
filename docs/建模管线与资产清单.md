# 建模管线与资产清单

版本 v1.1 · 2026-10-17 · Blender 5.2.2 LTS

这份文档记录街区模型是怎么来的、一共多少件、怎么改、怎么重出。上一轮那套「程序化几何直接在 Three.js 里拼」的做法已经停用，现在是 Blender 出 GLB，Three.js 只负责加载、合并和摆位。

## 一、为什么不用外部资产

| 方案 | 代表 | 结论 |
| --- | --- | --- |
| 付费日式低模包 | Akochan 60 件套、studio³ 七栋、Mixall | 授权是 royalty-free，但禁止再分发，不能进仓库；风格也不统一，混用会崩 |
| CC0 免费包 | Quaternius、Kenney、KayKit | 授权最省事，但全是欧美城市，日式街景对不上 |
| 自建 | Blender + bpy 脚本 | 尺寸、配色、面数全在自己手里，49 件风格一致，能复现 |

结论是自建。脚本化的好处很实在，改一个常量重跑一次，全部资产同步更新，不会出现「这栋改了那栋忘了」。

## 三、招牌怎么做的

招牌是这一轮返工最多的地方。

模型里的招牌拆成四件，背箱、内凹面板、上下铝型材、顶部灯带。面板本身是纯色，不吃任何文字。导出时给面板打一个 `role=sign` 的自定义属性，属性跟着 extras 进 GLB。

Three.js 加载后按这个标记读出面板的包围盒，算出宽高比，用 Canvas 现画店名贴上去。宽高比对上了，字才不会被压扁。侧挂竖招同理，标记是 `role=blade`，竖排逐字画。

这样做的代价是招牌字不是真几何，远看会有点平。换来的是同一套门脸能服务多家店，加一家店不用回 Blender。

## 四、坐标与命名约定

- 单位 1 = 1 米，Z 轴向上，建筑正面朝 -Y，原点在底面中心。
- 导 glTF 时默认转 Y-up，正面变成 +Z，正好对上 Three.js 里既有的「门脸朝 +Z」约定，摆位时 `rotation.y = rotY` 不用改。
- 招牌面、竖招面在 Blender 里分别打 `role=sign` 与 `role=blade`。

## 五、性能

Blender 出来的每件资产有几十个小物件，直接克隆会产生上百个 draw call。加载时按材质合并成「每种材质一个 mesh」之后，一整间店只剩十来次绘制。

| 项 | 数值 |
| --- | --- |
| 资产三角面合计 | 58,488 |
| 场景 mesh 数 | 940（合并前 3133） |
| draw call | 303 |
| 同屏三角面 | 48,328 |

街道家具是静态的，摆位之后又按材质烘焙成一整批，几十件道具总共只占十来个 draw call。

## 六、怎么改、怎么重出

在 Blender 里（通过 MCP 或界面）跑下面这行

```python
exec(open("D:/Desktop/Game/tools/blender_kit.py").read())
```

脚本会清场、重建 49 件资产、逐个导出 GLB、出三张预览图、保存 `assets/SakuraBlock_Kit.blend`。

只改尺寸就动 `tools/blender_kit.py` 里的常量，建筑面宽在 `build_shop` 的 `W`/`D`，层高 `FH`，瓦片和墙面颜色在 `build_materials`，门脸差异在文件末尾的 `STYLES` 表。

预览可以单独出图，不重建模型。

```python
exec(open("D:/Desktop/Game/tools/blender_preview.py").read())
```

## 七、设计上踩过的坑

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| 招牌烘字 | 一套门脸只能服务一家店，加店就得重出模型 | 招牌留空，店名改由 Canvas 贴图运行时叠加 |
| 招牌比例 | 纹理按 3.2 比 1 画，贴到 8 比 1 的面板上，字被压扁 | 纹理宽高比改成按包围盒动态算 |
| 屋顶悬空 | 山墙底边比墙顶高 0.1 米，侧看是一块浮板 | 屋顶基面压到墙顶，加封檐板盖住接缝 |
| 玻璃像白纸 | 玻璃后面没有东西，纯色发光面读不出纵深 | 玻璃后加暗室内壁与货架剪影 |
| 团地背面是灰板 | 只给临街面开了窗 | 正、背、侧三面都开窗 |
| 招牌无 UV | bmesh 生成的方块没有 UV，贴图贴不上去 | 单独出一块平面，按包围盒定位 |
| 路面塑料感 | 材质每帧被雨效写死成粗糙度 0.72、金属度 0.08，贴图被乘掉 | 干燥时给 1.0，让粗糙度贴图说了算 |
