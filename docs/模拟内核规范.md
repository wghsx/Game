# 模拟内核规范

版本 v0.1 · 2026-10-15 · 配套《3D资产制作规范》《街区与场景建模规范》

资产与场景定的是世界长什么样，本文定的是世界怎么动。

## 1. 时间推进：连续与日结算混合

时间分两条通道走，这是整套模拟的分界线，后面每个系统都要归到其中一条。

**连续通道**，每游戏分钟推进一次，跑玩家看得见的东西：

- 店铺营业状态（门口招牌亮不亮、有几个人在逛）
- 人流与 NPC 走动
- 天气的视觉表现
- 玩家的移动与交互判定

**日结算通道**，每个游戏日执行一次，跑玩家看不见但决定成败的东西：

- 户的收入、消费、通勤
- 店铺的当日营业结算
- 资金收支
- 满意度重算
- 人口增减
- 等级经验累积

结算时刻定在**每日 04:00**，不是 00:00。居酒屋这类店铺深夜还在营业，卡在午夜结算会把跨零点的营业额算错。

## 2. 时间尺度与倍速

| 项 | 值 |
| --- | --- |
| 时间映射 | 1 游戏小时 = 1 真实分钟 |
| 一游戏日 | 24 真实分钟 |
| 一个 tick | 1 真实秒 = 1 游戏分钟 |
| 倍速档位 | 1× / 2× / 4×，另有暂停 |
| 4× 的限制 | 人物与车辆动画速度封顶在 2×，其余系统按 4× 推进 |

人物动太快会糊成一团，比慢还难受，所以 4× 时只加速时间和结算，不让腿也变快。

## 3. 模拟保真度：真源与表现分离

**模拟真源只有两层，户和店。** 屏幕上的 NPC 是表现，不是真源。

- NPC 从统计模型按概率抽出来演，走完就回收，不留个体数据。
- 玩家按 E 与某个 NPC 交互时，才临时给这一个 NPC 生成一份个体档案，交互结束即丢弃。
- 一屏 NPC 上限 40 个，这个数字是表现层的预算，与模拟规模无关。

这条决定的后果很大：模拟规模可以远超屏幕上能看到的人。玩家只在心里觉得街上有人，系统并不需要真的养着这些人。

## 4. 模拟基本单位

| 单位 | 说明 | 数量级 |
| --- | --- | --- |
| 户（Household） | 居住单位，2 到 4 人，带收入、满意度、通勤需求 | 数十到数百 |
| 店（Shop） | 经营单位，占地块，带营业额、员工需求、供货需求 | 十到数十 |
| 人（Person） | 只在需要展示或交互时生成 | 0 到 40（同屏） |

人不是模拟单位，不进循环，不存档。

## 5. 确定性

- 全局使用固定种子，模拟推进是确定性的：同种子加同操作，必然复现同一结果。
- 每个街区另有独立种子（见 ADR-0008），只影响街景生成，不影响经济模拟。
- 确定性带来一个实打实的好处：出问题可以复现。把种子和操作序列记下来，就能重放。

## 6. 存档内容

| 存 | 不存 |
| --- | --- |
| 全局种子与各街区种子 | NPC 的个体数据 |
| 所有 pin 记录 | 每帧的临时状态 |
| 户与店的完整状态 | 派生值（可重算的，一律不存） |
| 资金、时间、等级、满意度 | 图片缓存之类可以重建的东西 |

派生值不存是一条硬规矩。存了就会出现「存档里的值和重算出来的值不一致」这类很难查的 bug。

## 7. 首版系统范围

做：

| 系统 | 归属通道 |
| --- | --- |
| 时间与天气 | 两条都有 |
| 住户与人口 | 日结算 |
| 店铺经营 | 两条都有 |
| 经济收支 | 日结算 |
| 满意度 | 日结算 |
| 街区性格 | 日结算 |
| 巡视配额 | 连续 |
| 街区争霸 | 两条都有 |

明确不做：物流与供应链、员工个人成长、多街区协同、随机事件系统、街景演化与节气周期（后两者移到 v1.1，见《玩法候选池》）。

范围不划死，模拟经营的第一个版本永远做不完。

## 8. 日结算的执行顺序

顺序不能乱，后面的计算依赖前面的结果：

1. 户收入入账
2. 通勤与消费（决定店铺客流）
3. 店铺当日营业额结算
4. 资金收支汇总（抽成、租金、维护）
5. 满意度重算
6. 人口增减（有人搬走或搬进）
7. 性格纯度与等级累积
8. 影响力扩散与控制度更新（见《街区争霸规范》）
9. 并入判定

## 9. 验收

- 同一存档连读两次，推进 10 个游戏日，两次的资金与人口数值完全一致。
- 4× 倍速下人物步态不出现明显跳帧。
- 单独重算任一日的结算，结果与当日实际记录一致。
